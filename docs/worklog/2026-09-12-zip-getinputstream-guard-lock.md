# 2026-09-12 — `ZipFile.getInputStream` 가드 잠금 — ★**`ZipOutputStream` 을 «만들지 않았다»**

채택 제안 `2026-09-12-null-guard-spec-triage#p0`.

## ★결론 먼저 — 제안의 «근인 진단»이 틀렸다

제안 문면: 「픽스처가 `ZipFile` 을 못 만들어 잠기지 않는다 · **근인은 `ZipOutputStream` 부재**」.
★**근인은 그것이 아니다** — `ZipFile` 인스턴스를 만들려면 **zip 이 하나 있으면 되고, 그것을 «런타임이 만들» 필요가 없다.**
⇒ ★**`ZipOutputStream` 구현 0줄** · ★**런타임(`.rs`) 변경 0줄** · 산출물은 **픽스처 하나**다.

★**티켓이 이 결말을 미리 허용했다**(대전제 ⓑ: 「미리 만든 zip 같은 다른 경로가 있으면 **런타임을 구현하지 않는 것이 더 싼 답**이고 그것이 결론일 수 있다」).

## ⓐ 「단일 제거해도 green」 재현 (착수 시)

`zip_file.get_input_stream(entry)` 가드만 제거 → `cargo test --test test_class` **ok** ⇒ ★**잠기지 않은 것이 맞다**(직접 증거).

## ⓑ 더 싼 경로를 «두 단계» 내려갔다

1. **미리 만든 zip 을 커밋한다** — `python3 -m zipfile` 로 STORED zip 을 만들어 `test-data/ziptest.zip` 에 두니 **왕복이 성립**했다
   (`ZipFile(File)` → `getEntry` → `getInputStream`). ⇒ 이 시점에 이미 `ZipOutputStream` 은 **불요**로 판명.
2. ★★**그런데 새 바이너리조차 필요 없었다** — `test-data/test.jar` 가 **이미 있고 jar 은 zip 이다**.
   ⇒ `ziptest.zip` 을 **지웠다**. ★**이 회차가 추가한 바이너리 = 0.**

★**하버스가 확장자로 거른다**(`x != "class" && x != "jar"` ⇒ `.zip` 은 건너뛴다) — 그래서 1안도 안전했지만, 2안이 **더 싸다**.
★**아카이브 «내용»에 의존하지 않는다** — 픽스처는 `getEntry` 를 부르지 않고 **열리기만 하면** 된다.
⇒ 누가 `test.jar` 의 내용을 바꿔도 이 시험은 안 깨진다(결합도를 일부러 낮췄다).

## 범위 — «여기까지»

- ★`ZipOutputStream` **미구현** · deflate·압축 레벨·`ZipEntry` 부가 메타 **무접촉**(계약 3) · 다른 가드 리니지 **무접촉**.
- ★`.rs` **0줄** — 계약 2 의 「잃는 것 = deflate 미구현」은 ★**애초에 발생하지 않는다**(구현 자체를 안 했으므로 잃은 기능이 없다).
- ★**남은 한계는 «다른 것»이다**: 이 repo 에 **게스트가 zip 을 «쓰는» 경로가 여전히 없다**(`ZipOutputStream` 부재).
  그것이 필요해지는 것은 **「게스트가 zip 을 만든다」는 요구가 실제로 생길 때**이지 **가드 잠금 때문이 아니다** — 그 둘을 섞지 마라.

## 부수 관측 (고치지 않았다)

`java/util/zip/ZipFile.close()` 가 **등재돼 있지 않다** — 픽스처 초판이 `zf.close()` 를 불러 `NoSuchMethodError` 가 났다.
★**이 회차 범위 밖**이라 손대지 않고 픽스처에서 그 호출을 뺐다(주석으로 사유를 남겼다). 실제 게스트 코드는 `close()` 를 흔히 부르므로 **후속 소재**다.

## 제안
- p0: `ZipFile.close()` 등재 — 게스트가 흔히 부르는데 `NoSuchMethodError` 가 난다(이 회차가 픽스처에서 실제로 밟았다).
