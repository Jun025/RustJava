# 2026-09-18 — 다섯 픽스처는 `-g` 로 만들어졌다 (rustjava-adopt-javac-fixture-provenance-verified-p0)

채택 제안 `2026-09-17-javac-fixture-provenance-verified#p0` —
「루트 픽스처 다섯이 왜 커밋된 바이트로 재빌드되지 않는지 알아내라」의 처분이다.
★**제품 Rust 0줄 · 커밋된 `.class` 바이트 0 변경.**

## 답 — `-g` 다

커밋본은 **디버그 정보를 달고** 컴파일됐고, 검증 스크립트는 **그것 없이** 재빌드하고 있었다.
javac 의 기본은 `-g:lines,source`(`LineNumberTable`+`SourceFile`)라 `LocalVariableTable` 은 **안 나온다**.

| 픽스처 | `-g` 없이 | `-g` |
|---|---|---|
| `MonitorSemantics` · `$CounterWorker` · `$FailingWorker` (`--release 8`) | 다름 | ★**바이트 동일** |
| `NativeMethod` (`--release 8`) | 다름 | ★**바이트 동일** |
| `OddEven` (`--release 21`) | 다름 | ★**바이트 동일** |

처음 단서는 `javap -v -p` 대조였다 — 커밋본(902B)에만 `LocalVariableTable` 과 그 이름들
(`this`·`args`·`oe`·`arg`·`i`)이 있고 재빌드본(709B)에는 없다.

## ★제안의 «두 설명»은 둘 다 틀렸다

제안 `why` 는 「**다른 컴파일러**와 **픽스처를 만든 뒤 편집된 소스**가 둘 다 이것을 설명한다」고 적었다.
측정은 **둘 다 반증한다**:

- **컴파일러 아니다** — 같은 다섯이 **26.0.1 과 26.0.2.1 에서 똑같이** 다르고, 둘 다 `-g` 를 주면
  **똑같이 바이트 동일**하다(두 판본을 각각 직접 돌려 확인 · 26.0.1 keg 가 남아 있어 가능했다).
  ※제안은 26.0.1 에서 측정됐고 이 회차는 26.0.2.1 이 기본인 맥에서 쟀는데 **수가 같았다** — 그 자체가 첫 반증이다.
- **소스 발산 아니다** — `-g` 만 주면 **지금 소스가 커밋된 바이트를 정확히 낸다**. 소스와 픽스처는 **어긋나 있지 않다.**

★★**그래서 제안이 가장 걱정한 대가가 «사라진다»**: 제안 `tradeoff` 는 「두 번째 경우의 처방은 재컴파일이고,
여러 시험이 픽스처 출력을 커밋된 `.txt` 와 비교하므로 재컴파일이 **동작 변경**이 될 수 있다」였다.
⇒ ★**재컴파일이 필요 없다.** 이 회차는 `.class` 를 **한 바이트도** 건드리지 않았다.

## 고친 «한 자리»

스크립트는 이미 **`--release` 를 픽스처 자신에서** 읽는다(「nothing external has to be consulted or kept in sync」).
★**`-g` 도 같은 자리에서 같은 방식으로** 읽게 했다 — 커밋된 클래스의 상수풀에 `LocalVariableTable` 이 있으면 `-g`.

★**배선 «전»에 판별력을 쟀다**: `test-data` 전체에서 `LocalVariableTable` 보유는 **정확히 5개**,
미보유 **107개**이고 그 5개가 **바로 그 다섯**이다 — ★**5/5 · 오탐 0**.

## 검증 — 양방향

| | 결과 |

| 고친 뒤(정상) | ★**109 rebuilt: 109 reproduced, 0 differed** |
| ★개악 — `-g` 파생 **한 줄**을 no-op 으로 | ★**104 reproduced, 5 differed** · ✗ 목록이 **원래 다섯과 동일** |
| 복원 | 0 differed |

`cargo test --all` **579 passed / 0 failed / 1 ignored**(불변 — Rust 무접촉).

## ★잃는 것 — 그리고 «안 하면 무엇이 나쁜가»

- ★**스크립트는 여전히 `rc=1` 이다.** 재빌드 불가 **3건**(`ConstantsReader`·`IncompatibleStatic`·
  `VirtualDispatchSemantics`)이 남아 있고, 그것은 제안이 **따로 미해결로 적어 둔 축**이다(형제가 필요한 소스 ·
  `-sourcepath` 를 일부러 안 쓴다 — `test-data/src/Exception.java` 가 `java.lang.Exception` 을 가리기 때문).
  ⇒ ★**드리프트 질문은 답했고, 종료 코드는 아직 0 이 아니다.** 넓히지 않았다.
- ★**파생 축이 하나 늘었다** — 누군가 `-g:none` 으로 다시 만들어 커밋하면 그 속성이 **조용히 사라지고**
  스크립트는 그것을 「드리프트」로 읽는다. 의도한 읽기이지만, **판정이 한 속성의 유무에 걸린다**는 뜻이기도 하다.
- ★**안 하면**: 스크립트가 **영구히 거짓 드리프트 5건**을 보고한다. 그러면 ⑴「재컴파일해서 맞추자」는
  제안의 `tradeoff` 대로 **정말로 동작 변경 위험**을 감수하게 되거나 ⑵다음 사람이 **같은 조사를 처음부터 다시** 한다.
  ★그리고 이 스크립트는 「픽스처를 재생성했을 때 사람이 돌리는 검사」라 ★**거짓 경보가 그 유일한 용도를 무디게 한다.**

## 후속

- ★**재빌드 불가 3건** — 형제를 참조하는 소스를 어떻게 컴파일할 것인가(`-sourcepath` 없이).
  ★제안이 「이걸 정하지 않으면 조사가 완결되지 않는다」고 적은 그 축이고, **여기서 넓히지 않았다.**
