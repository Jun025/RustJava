## ⓐ 「3건」을 다시 셌다 — ★**4건이다**

두 해소 커밋 각각에서 base·ours·theirs 의 정의 집합을 세고 `theirs − 결과` 를 냈다:

```
e53b2142 (merge-base 4b89f18a)  base 14 · ours 20 · theirs 18 · 결과 20  → 떨어진 것 4
514d5b08 (merge-base 42e99a7e)  base 18 · ours 20 · theirs 18 · 결과 20  → 떨어진 것 4
   const LINKED · const MAKECONCAT_DESCRIPTOR · def make_concat_call_site · method fieldref
```
제안은 **three** 라 적었다. ★**내 정의로는 4**이고, 넷째는 `MAKECONCAT_DESCRIPTOR` 다. ※쓰기 루프는 `if __name__` 안이라 «정의»가 아니어서 안 센다 — 그 한계는 아래에 적는다.

## ⓒ 「최상위 정의」를 무엇으로 볼 것인가 — ★실제 4건에서 거꾸로 정했다

| 떨어진 것 | 계급 |
|---|---|
| `LINKED` · `MAKECONCAT_DESCRIPTOR` | 모듈 수준 대문자 대입 |
| `make_concat_call_site` | 모듈 수준 `def` |
| ★`fieldref` | ★**`class Pool` «안»의 메서드**(들여쓰기 4) |

⇒ ★★**「최상위」만 보면 4건 중 3건만 잡는다.** 그래서 **한 단계 중첩(메서드)까지** 본다. Rust 도 같은 모양으로 넣었다(`fn`·`type`·`const`·`impl` 안 메서드).

## ⓓ 스쿼시와의 상호작용

`rustjava` 는 `contracts/upstream-sync-repos.conf` **등재**라 **`--merge` 로 착지**한다 ⇒ main 에 **부모2가 있다**(최근 200 커밋 중 머지 **83**).
★**그러나 이 검사기가 겨냥하는 것은 착지가 아니라 «브랜치 내부 base 당김 머지»**이고(사고 둘 다 그것이었다 · 최근 83 중 **26건**),
그것은 **착지 방식과 무관하게** 존재한다. ⇒ **PR 시점에** 검사하므로 스쿼시 repo 에서도 같은 값을 한다.
실측: 부모 1개짜리 범위 → `0 merge(s)` · **rc=0**(조용히 통과하고, 그것이 문서화된 동작이다).

## 의도와 사고를 가르는 목록 — ★**커밋 trailer 다**

```
Dropped-from-theirs: Pool.fieldref -- superseded by the new pool builder, see <round>
Dropped-from-theirs: * -- recorded as a merged ancestor only, our tree is authoritative
```

- **어디에**: 그 **머지 커밋 메시지**에.
- **누가 언제 지우는가**: ★**지울 필요가 없다** — trailer 는 **자기 커밋 하나만** 면제한다.
  ★티켓이 경고한 「영구 목록은 시간이 지나면 검사기를 무력화한다」가 **구조적으로 불가능**하다(파일이면 항목이 쌓여 검사기를 끈다).
- **왜**: `--` 뒤 사유가 **형식상 필수**다(없으면 매치되지 않아 면제되지 않는다).

## ★★설계를 한 번 갈아엎었다 — 개악 시험이 «내 검사기»의 구멍을 잡았다

초판에는 **구조적 면제**가 있었다: 「결과 트리 == 부모1 트리면 `-s ours` 이니 건너뛴다」.
★**개악 시험이 그것을 무너뜨렸다** — theirs 를 통째로 버린 합성 머지도 **트리가 부모1과 같아서**
★**면제에 삼켜져 rc=0 이 됐다.** 그런데 그게 **이 검사기가 존재하는 이유인 바로 그 실패**다.
⇒ ★**구조적 면제를 걷어내고 «선언»(`*` 와일드카드)으로 바꿨다.** `-s ours` 도 이제 **말해야** 한다.
★이 교체가 이 회차에서 가장 값한 측정이다 — 양방향을 안 돌렸으면 **끈 채로 착지**했다.

★**그리고 CI 는 이 범위를 돌지 않는다** — `origin/main..HEAD`(= PR 범위)만 본다. 과거 머지는 재검사되지 않으므로 이 8건이 main 을 red 로 만들지 않는다.
⇒ PR 하나에 내부 머지는 보통 **0~2건**이라 **실비용 ≈ 0~9초**.
